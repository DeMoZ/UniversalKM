# Proposal

## Why

Mac уже управляет ChameleonUltra и без кабеля: в `add-ble-hid-input-bridge` (задача 1.15, релиз 0.1.0) приложение подключается к Chameleon по Bluetooth как BLE central и шлёт те же кадры `netdata` через штатный сервис Nordic UART (NUS); если выдернуть USB, работа продолжается по Bluetooth. Но у этого канала три проблемы, найденные при проверке на устройствах:

- **Дыра в безопасности.** В режиме HID без PIN NUS открыт без шифрования, а прошивка выполняет пришедшие по нему кадры, включая `UKM_HID_KEYBOARD` (9002). Любой телефон рядом может подключиться к Chameleon и набирать текст на сопряжённых устройствах пользователя.
- **macOS сама сопрягается с Chameleon как с клавиатурой.** Когда приложение подключается через CoreBluetooth, система видит HID‑сервис, проходит сопряжение (bond, peer ID) и подписывается на отчёты. Отчёты Mac не получает (прошивка не считает соединение управления хостом), но Chameleon появляется в настройках Bluetooth Mac как клавиатура, а после выхода приложения система держит соединение.
- **Mac занимает одно из трёх соединений,** поэтому, пока приложение работает, хостов может быть только два.

## What Changes

- **Защищённый канал управления вместо NUS.** В прошивке появляется отдельный GATT‑сервис UniversalKM (свой 128‑битный UUID): характеристика для пакетов от Mac (запись без ответа) и характеристика для уведомлений о состоянии. Канал управления приложения (`ChameleonBLELink`) переходит с NUS на этот сервис. Через него проходит то же, что сейчас через NUS: включение режима HID, отчёты мыши и клавиатуры адресату, нейтральные отчёты и состояние хостов.
- **Защищённое сопряжение Mac ↔ Chameleon, один раз по кабелю.** Пока Chameleon подключён по USB, приложение создаёт случайный ключ, хранит его в связке ключей и записывает в Chameleon. Беспроводной сеанс начинается со взаимной проверки этого ключа, а все пакеты шифруются и подписываются ключом сеанса (защита от подслушивания паролей, подмены и повтора). Системного Bluetooth‑сопряжения Mac с Chameleon нет: Mac не видит Chameleon как свою клавиатуру.
- **Команды режима HID не принимаются по NUS** в режиме HID — только по USB и по защищённому каналу UniversalKM. Штатные команды Chameleon по NUS работают как раньше.
- **Выбор канала в приложении — как сейчас.** USB, пока кабель подключён; Bluetooth‑канал держится в запасе и подхватывает работу, когда кабель выдернут (решение пользователя в базовой задаче 1.15). Это уже работает; меняется только сервис, через который идёт Bluetooth‑канал.
- **Хосты и Mac одновременно.** Chameleon держит до трёх хостов (телефоны, планшеты) и ещё одно соединение с Mac (сейчас Mac занимает одно из трёх). Соединение, открывшее сеанс UniversalKM, не HID‑хост и не появляется на схеме (так уже сделано для NUS‑канала).
- **Батарея.** Без USB и без связи с Mac Chameleon уже сейчас выключает режим HID и засыпает по правилам апстрима (базовое требование «Выключение режима HID без связи с Mac»). Добавляются: заряд батареи Chameleon в панели, предупреждение при низком заряде и замер времени работы без кабеля.
- **Панель в строке меню:** канал связи («USB» / «Bluetooth» / «ищу Chameleon…» / «не сопряжён»), кнопки «Сопрячь для работы без кабеля» и «Забыть Chameleon», статус разрешения Bluetooth. Ключ `NSBluetoothAlwaysUsageDescription` уже есть в `Info.plist` (базовая 1.15).

## Capabilities

### New Capabilities

- `chameleon-wireless-link`: беспроводная связь Mac ↔ ChameleonUltra — сопряжение по кабелю, поиск и подключение по BLE, проверка ключа, шифрование и защита от повтора, передача отчётов и состояния, выбор между USB и Bluetooth, отказ в командах HID через NUS, сон и батарея Chameleon, отображение в панели.

### Modified Capabilities

(нет — в `openspec/specs/` ещё нет спецификаций. Требования к `ble-hid-peripheral` и `menu-bar-app` из незаархивированного `add-ble-hid-input-bridge` не меняются; новое поведение описано в `chameleon-wireless-link`. Единственное противоречие — фраза «Приложение само Bluetooth не использует» в proposal того изменения — снимается задачей в tasks.md.)

## Impact

- **Зависит от `add-ble-hid-input-bridge`:** HID‑прошивка, транспорт `HIDTransport` с каналами USB и Bluetooth (NUS), панель — всё это уже есть (релиз 0.1.0). Изменение заменяет NUS‑канал и снимает его проблемы.
- **Прошивка:** новый `firmware/src/ukm_link.c/.h` (сервис, сеанс, шифрование через `nrf_crypto` CC310 — ChaCha20‑Poly1305 и HKDF уже включены в `sdk_config.h` апстрима), хранение ключа во флеше (FDS), правки `ukm_hid.c` (Mac‑соединение не HID‑хост, внутренняя очередь клавиатуры), патчи: `NRF_SDH_BLE_PERIPHERAL_LINK_COUNT` 3 → 4, `NRF_SDH_BLE_VS_UUID_COUNT` 1 → 2, RAM SoftDevice, фильтр команд 9001–9003 из NUS в `app_cmd.c`, таймер сна. Новые USB‑команды 9010–9012 (сопряжение). Протокол режима HID — версия 3.
- **Приложение:** `ChameleonBLELink` переходит с NUS на сервис UniversalKM с сеансом; переключение USB ↔ Bluetooth в `ChameleonHIDTransport` остаётся; хранение ключа в Keychain, кодек пакетов и сеанса в Core (CryptoKit: ChaChaPoly, HKDF) с unit‑тестами и тестовыми векторами, общими с прошивкой. Новый фреймворк CoreBluetooth; сторонних зависимостей нет.
- **Разрешения:** Bluetooth уже запрашивается (базовая 1.15). Меняется момент запроса: только при «Сопрячь…» или сохранённом ключе. Accessibility и Input Monitoring — без изменений.
- **Задержка:** беспроводной канал добавляет ~15–30 мс к пути курсора (интервал соединения macOS) против ~1–2 мс по USB. USB остаётся и выбирается автоматически, когда кабель подключён.
- **Батарея:** время работы Chameleon без кабеля неизвестно и измеряется в задачах; результат идёт в README.
- **Безопасность:** закрывается ввод текста на телефон через открытый NUS в режиме HID — дыра есть в опубликованном 0.1.0, поэтому это изменение в приоритете.
