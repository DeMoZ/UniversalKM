# Tasks

Работа идёт тремя шагами по просьбе пользователя. **После каждой группы (шага) — остановка: показать результат и ждать подтверждения пользователя.** Внутри шага 1 есть отдельная точка остановки после spike (задача 1.3).

## 1. Шаг 1 — каркас проекта и BLE HID периферия (Модуль 1)

- [ ] 1.1 Создать `Package.swift` (macOS 14, Swift 6) с таргетами `UniversalKMCore`, `UniversalKM` (executable), `UniversalKMCoreTests`, а также `.gitignore` (`.build/`, `build/`). Проверка: `swift build` и `swift test` проходят на пустых заготовках.
- [ ] 1.2 Добавить `Resources/Info.plist` с ключами из design D2 (`LSUIElement`, `NSBluetoothAlwaysUsageDescription` и др.), `Resources/UniversalKM.entitlements`, а также `scripts/build-app.sh` и `scripts/run.sh` (подпись Apple Development, предупреждение при ad‑hoc fallback). Проверка: скрипт создаёт `build/UniversalKM.app`, `codesign -dv` показывает идентичность, `plutil -lint` проходит, приложение запускается без значка в Dock.
- [ ] 1.3 **Spike осуществимости:** минимальный `BluetoothHIDServer` публикует HID 0x1812 со всеми характеристиками и Report Reference 0x2908 (design D3), Device Information и Battery, и начинает рекламу. Проверка: в логе нет ошибок `didAdd service`; Android (nRF Connect) видит все сервисы и дескрипторы; сопряжение с Android и с iPhone проходит. **Если сервис или дескриптор отклонён — остановиться и вынести варианты из design (Risks) на решение пользователя.**
- [ ] 1.4 Реализовать в Core `HIDReportDescriptor` (байты Report Map по design D4) и `HIDReports` (кодирование 8‑байтового отчёта клавиатуры и 7‑байтового отчёта мыши, int16 LE, clamp). Проверка: unit‑тесты — golden‑байты Report Map, кодирование отрицательных X/Y, clamp ±32767, 6 клавиш + модификаторы.
- [ ] 1.5 Реализовать в Core `MouseAccumulator` (суммирование dx/dy/wheel/pan в `Double`, перенос дробного остатка и остатка сверх диапазона, отдельный отчёт при смене кнопок, design D5). Проверка: unit‑тесты — сумма отправленного движения равна сумме входного (округлённой); 10 смещений по 0,3 дают в сумме 3; при смене кнопки накопленное движение уходит раньше отчёта с кнопкой.
- [ ] 1.6 Довести `BluetoothHIDServer`: своя очередь `ble.hid`, обработка `peripheralManagerDidUpdateState`, подписка и отписка как подключение и отключение (design D6), остановка и возобновление рекламы, отправка через `updateValue` с ожиданием `peripheralManagerIsReady`, FIFO для клавиатуры с приоритетом над мышью, ответы на чтение Report Map, Protocol Mode и Battery, приём output‑отчёта и Control Point, публичный API `sendMouse(dx:dy:buttons:wheel:pan:)`, `sendKey(...)`, `sendNeutral()`, поток статусов. Проверка: `swift build` без предупреждений Swift 6 concurrency.
- [ ] 1.7 Временный режим `UniversalKM --ble-demo`: после подписки хоста курсор проходит квадрат, выполняется клик, печатается `hello`, затем `sendNeutral()`. Проверка вручную на Android и iPhone (с AssistiveTouch): курсор рисует квадрат, клик срабатывает, в заметках появляется «hello», повторное подключение после перезапуска приложения проходит без нового сопряжения, отключение телефона возвращает рекламу (лог).
- [ ] 1.8 Написать `README.md`: требования, сборка (`scripts/build-app.sh`, `SIGN_IDENTITY`), ключи Info.plist и зачем они нужны, сопряжение с Android и iOS (AssistiveTouch), режим `--ble-demo`. Проверка: команды из README выполняются как написано.

## 2. Шаг 2 — перехват ввода (Модуль 2)

- [ ] 2.1 Реализовать в Core `KeyCodeMap` (virtual keycode macOS ANSI/ISO → HID Usage, модификаторы L/R → биты, design D10). Проверка: unit‑тесты на буквы, цифры, F1–F12, стрелки, Return/Esc/Tab/Delete/ForwardDelete, все 8 модификаторов; клавиша без отображения возвращает `nil`.
- [ ] 2.2 Реализовать в Core модель `DeviceArrangement` (Codable) и `ArrangementLayout` для расчёта прямоугольника устройства и зоны передачи, включая расположение по умолчанию и флаг `isTemporary` (design D8). Проверка: unit‑тесты — расположение по умолчанию справа по центру; зона для каждой из 4 сторон; книжная и альбомная ориентация дают разную длину зоны; часть края, к которой примыкает другой дисплей, из зоны исключена; без якорного UUID — расположение по умолчанию и `isTemporary`; JSON туда и обратно без потерь.
- [ ] 2.3 Реализовать в Core `HandoffZoneDetector` (design D8). Проверка: unit‑тесты — точка в зоне при движении наружу срабатывает на всех 4 сторонах; тот же край вне зоны не срабатывает; движение вдоль края или внутрь не срабатывает; граница между двумя дисплеями не срабатывает.
- [ ] 2.4 Реализовать в Core `Hotkey` (модель, `isValid`, сопоставление по keyCode и точному набору модификаторов, значение по умолчанию, design D11). Проверка: unit‑тесты — Ctrl+Opt+Cmd+Esc по умолчанию; Esc без модификаторов и Shift+Esc недопустимы; лишний модификатор не совпадает; CapsLock и Fn игнорируются.
- [ ] 2.5 Реализовать в Core `CaptureStateMachine` (design D11). Проверка: unit‑тесты — `zoneHit` без хоста или без устройства игнорируется; `zoneHit` с хостом → `remote` + hide/lock; `hotkey`/`hostDisconnected`/`permissionLost`/`tapDisabled`/`deviceRemoved`/`quit` из `remote` → `local` + show/unlock/`sendNeutralReports`; повторный hide не выдаётся.
- [ ] 2.6 Реализовать `DisplayLayoutProvider` (дисплеи, UUID, главный, `CGDisplayRegisterReconfigurationCallback`) и `InputManager`: event tap `.cghidEventTap`/`.defaultTap` на отдельном потоке с `CFRunLoop`, потокобезопасное состояние (`OSAllocatedUnfairLock`) — режим, зона, горячая клавиша; горячая клавиша первой в колбэке; повторное включение при `tapDisabled*` с release. Пока нет UI, используются телефон в расположении по умолчанию и горячая клавиша по умолчанию. Проверка вручную: в режиме Mac всё работает как обычно (набор текста, клики, прокрутка, перетаскивание окна); подключение и отключение монитора пересчитывает зону (лог).
- [ ] 2.7 Реализовать захват и возврат курсора (warp на 2 точки внутрь от зоны, `CGAssociateMouseAndMouseCursorPosition`, `CGDisplayHideCursor`/`ShowCursor` парами, design D9) и пересылку событий в `BluetoothHIDServer` (движение, кнопки, dragged, прокрутка со слиянием, клавиши без autorepeat, flagsChanged, design D10). Проверка вручную с Android: правый край в пределах зоны → курсор Mac замер, ввод идёт на телефон, Mac не получает кликов и нажатий; тот же край вне зоны → захвата нет; горячая клавиша возвращает курсор в точку захвата; выключение Bluetooth на телефоне возвращает курсор автоматически. **Ускорение (design D10):** залогировать дельты при одном и том же физическом движении медленно и быстро, с ускорением на Mac включённым и выключенным. Ожидается: при выключенном ускорении суммы равны, при включённом быстрая сумма больше. Сравнить ощущение на телефоне с курсором Mac. Если дельты в tap окажутся сырыми (без ускорения) — остановиться и вынести вопрос на решение пользователя.
- [ ] 2.8 Проверить скрытие курсора из фонового агента (design D9, варианты а→б). Записать в design.md, какой вариант сработал. Если нужен приватный API (вариант в) — остановиться и спросить пользователя. Проверка: при захвате курсор Mac не виден над любым активным приложением.
- [ ] 2.9 Добавить в `README.md` раздел «Как работает захват»: зона передачи, горячая клавиша, автоматический возврат, ограничения (Secure Event Input, один хост, возврат только клавишей). Проверка: описание совпадает с поведением из 2.7.

## 3. Шаг 3 — приложение в строке меню: панель, расположение, горячая клавиша, разрешения (Модуль 3)

- [ ] 3.1 Реализовать `PermissionsManager` (design D12): проверка и запрос Accessibility и Input Monitoring, открытие разделов System Settings, опрос каждые 2 с, пока чего‑то не хватает. Проверка вручную: после `tccutil reset Accessibility com.universalkm.UniversalKM` панель показывает отсутствие разрешения, а после его выдачи перехват включается без перезапуска.
- [ ] 3.2 Реализовать `AppStateManager` (`@MainActor @Observable`, design D13): связывает сервер, InputManager, DisplayLayoutProvider и автомат; хранит `arrangement` и `hotkey` в `UserDefaults` и передаёт их в InputManager при изменении; `setOrientation(_:source:)` как единственная точка смены ориентации; имя подключённого хоста берёт из устройства на схеме (design D6); при `IsSecureEventInputEnabled()` выставляет предупреждение. Проверка: `swift build` без concurrency‑предупреждений; после перезапуска расположение и горячая клавиша восстанавливаются (лог).
- [ ] 3.3 Реализовать `UniversalKMApp` + `MenuBarView` (`MenuBarExtra` со стилем `.window`, `NSApp.activate()` при открытии): значок по режиму и типу устройства, статус Bluetooth («Ожидание подключения…» / «Подключено к <имя>» / выключен / нет доступа), место под схему, разрешения с кнопками, «Вернуть на Mac» (в режиме Устройство), «Выход». Режим `--ble-demo` оставить только за флагом. Проверка вручную по сценариям из `specs/menu-bar-app/spec.md` (кроме горячей клавиши).
- [ ] 3.4 Реализовать `ArrangementView` (design D14): дисплеи в системной раскладке без взаимодействия, главный отмечен, обновление при смене мониторов; выбор устройства кликом; кнопки «+» (форма: тип Телефон/Планшет + имя; недоступна при одном устройстве, с подсказкой) и «−» (удаляет выбранное; недоступна без выбора); слайдер «Скорость указателя» 0,25×–4× для выбранного устройства и строка «Ускорение мыши на Mac: вкл./выкл.»; перетаскивание с прилипанием через `ArrangementLayout.snap`; кнопка поворота; подсветка зоны; пометка «временное расположение» и «подключено». Unit‑тесты `snap` в Core: отпущен у каждого края — прилипает вплотную; отпущен над дисплеем — уходит к ближайшему свободному краю; не перекрывает соседний дисплей; `offset` сохраняется в долях. Проверка вручную по сценариям из `specs/device-arrangement/spec.md`, в том числе: поставить телефон слева снизу → захват срабатывает только там; «−» → захвата нет нигде; скорость 0,5× → движение на устройстве вдвое меньше и сохраняется после перезапуска.
- [ ] 3.5 Реализовать визуальные состояния схемы по таблице из design D14 (`ArrangementStyle`): дисплеи — обои, приглушённые, имя, полоска меню на главном, курсор‑стрелка, подсказка про System Settings; устройства — рамка акцентного цвета, иконка, точка статуса, наведение с открытой рукой; выбранное — толстая рамка с кольцом; перетаскивание — приподнятый полупрозрачный вид, сжатая рука, призрачный контур прилипания и предварительная зона; клик по пустому месту снимает выбор. Проверка вручную по сценариям «Дисплеи Mac выглядят некликабельными», «Устройства выглядят интерактивными», «Выбранное и перетаскиваемое устройство выделяется» в светлой и тёмной теме; снимки панели в каждом состоянии приложить к `docs/manual-test-results.md`.
- [ ] 3.6 Реализовать `HotkeyRecorderView` (design D14): показ текущего сочетания символами (⌃⌥⌘⎋), запись нового, отклонение недопустимого с пояснением, «Сбросить». Проверка вручную: задать ⌥⌘⌫ → оно возвращает на Mac, а ⌃⌥⌘⎋ уходит на устройство; попытка задать один Esc отклоняется; после перезапуска сохраняется ⌥⌘⌫.
- [ ] 3.7 Корректный выход: на `willTerminate` — release, показ курсора, пустые отчёты, `stopAdvertising`. Проверка вручную: «Выход» во время режима Устройство — курсор на Mac виден и работает, на телефоне ничего не залипло, устройство пропало из поиска.
- [ ] 3.8 Обновить `README.md`: панель, кнопки +/−, как разместить устройство и повернуть его кнопкой (автоматически ориентация не определяется — почему), скорость указателя и ускорение (Mac‑настройка учитывается сама; совет выключить ускорение на устройстве), горячая клавиша, разрешения (что и где включать), сброс разрешений, удаление сопряжения. Проверка: свежая установка по README проходит от начала до конца.
