# Proposal

## Why

После выхода из UniversalKM Android по Wi‑Fi через `adb` перестаёт работать у всех, пока сервер `adb` не перезапустить вручную. Найдено 2026‑11‑09 на macOS 27.0.1. Сервер `adb`, который запустило приложение, macOS считает частью UniversalKM, и доступ к локальной сети он получает по разрешению приложения, пока приложение работает. После выхода сервер продолжает работать, но каждое подключение получает «No route to host», хотя `ping` до телефона проходит: в Терминале телефоны висят в `offline`. Проверено:
- закрытие приложения в 14:15:28 и в 14:46:09 → в журнале `adb` сразу «No route to host»;
- сервер, запущенный из Терминала, работает;
- сервер, запущенный так, что отвечает сам за себя (`responsibility_spawnattrs_setdisclaim`, так делают терминалы), один раз вызвал запрос macOS «Локальная сеть» для `adb`. После разрешения он работает, кто бы его ни запустил и закрыт ли запустивший.

## What Changes

- **Приложение запускает сервер `adb` так, что тот отвечает сам за себя** (при старте и перед повторным запуском `track-devices`, когда сервер пропал). Тогда доступ к локальной сети у сервера свой, и выход из приложения его не ломает.
- **Один запрос macOS для `adb`.** В первый раз macOS спрашивает, разрешить ли `adb` доступ к устройствам в локальной сети. Ещё раз запрос появится после обновления platform-tools: путь к `adb` содержит версию. README говорит, что нужно разрешить и где это включить, если отказали.
- Сервер при выходе не останавливается: чужие сессии (`adb logcat` по USB, Android Studio) не обрываются.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `android-wifi-link`: новое требование «Сервер adb после выхода из приложения». Спецификация пока живёт в незаархивированном `add-android-usb-transport` (в `openspec/specs/` её ещё нет), поэтому дельта добавляет требование.

## Impact

- **Приложение:** `ADBClient.swift` (`ensureServer`: `adb start-server` через `DisclaimedSpawn`; повторный запуск `track-devices` сначала поднимает сервер), новый `DisclaimedSpawn.swift` (`posix_spawn` с `responsibility_spawnattrs_setdisclaim`, функция ищется через `dlsym`; без неё — обычный запуск), `AndroidHIDTransport.swift` (вызов `ensureServer`).
- **Зависимости:** `responsibility_spawnattrs_setdisclaim` — закрытый вызов macOS (его используют iTerm2, VS Code, Electron). Если его не станет, всё работает как раньше, с прежней ошибкой.
- **Разрешения macOS:** новое — «Локальная сеть» для `adb` (запрос один раз). Разрешение UniversalKM не меняется. Ключ `NSLocalNetworkUsageDescription` в приложении не нужен: спрашивают про `adb`, а не про приложение.
- **Ограничение:** сервер, который запустил не UniversalKM (например, `adb` из Терминала), живёт по правилам того, кто его запустил; это не меняется.
