# Design

## Context

Зачем и что — proposal.md, поведение — specs/android-files/spec.md.

Что есть сейчас:
- `ADBClient` находит пользовательский `adb`, поднимает сервер (`ensureServer`, с отказом от ответственности — fix-adb-server-local-network D1) и следит за списком устройств через `track-devices`. Все команды — запуск процесса `adb`.
- Android-устройство в схеме известно по серийному номеру (`ro.serialno`, он же iSerialNumber по USB): `AndroidPeerRegistry` хранит serial → peer ID, `PlacedDevice.hostPeerID` ссылается на peer ID.
- Приложение собирается SwiftPM и `scripts/build-app.sh` в один бандл, без песочницы (`UniversalKM.entitlements` пустой: фильтрующий CGEventTap в песочнице не работает). Релизы подписаны самоподписанным сертификатом «UniversalKM Self-Signed», у которого нет Team ID.

Ограничения File Provider, которые определяют подход:
- Расширение File Provider обязано работать в песочнице. Запустить из песочницы `/opt/homebrew/bin/adb` или `~/Library/Android/sdk/platform-tools/adb` нельзя.
- Расширение и приложение связываются через общую группу приложений (`NSExtensionFileProviderDocumentGroup`, право `com.apple.security.application-groups`). На macOS идентификатор группы должен начинаться с Team ID, а у самоподписанного сертификата его нет.

## Goals / Non-Goals

**Goals:** расширение, которое само говорит с сервером `adb`, без запуска процессов и без зависимости от того, работает ли приложение; разбор протокола `adb` в `UniversalKMCore` с тестами на записанных ответах.

**Non-Goals:** не встраиваем свой `adb` и не поднимаем сервер из расширения (это делает приложение, когда запущено; иначе — пользователь или Android Studio). Не кэшируем правки без связи. Не поддерживаем MTP.

## Decisions

### D1. File Provider (`NSFileProviderReplicatedExtension`), а не WebDAV, FUSE или своё окно
Это единственный способ получить место в боковой панели Finder с обычным поведением (перетаскивание, ход копирования, Quick Look, загрузка по требованию), без сторонних пакетов у пользователя.
*Альтернативы:*
- Локальный WebDAV-сервер в приложении и `mount_webdav`. Делается быстро, но WebDAV в Finder медленный, оставляет `._*` и `.DS_Store` на телефоне и показывает «Сервер отключён», когда телефон уходит из сети.
- macFUSE / FUSE-T. Пользователь ставит сторонний пакет; macFUSE на Apple Silicon ещё и требует ослабить защиту системы.
- Своё окно с файлами и перетаскиванием в Finder. Надёжно и проще, но это не Finder. Остаётся запасным вариантом, если D7 упрётся в подпись.

### D2. Расширение говорит с сервером `adb` по `127.0.0.1:5037` своим клиентом
Протокол хоста `adb` открыт (`OVERVIEW.TXT`, `SERVICES.TXT`, `SYNC.TXT` в исходниках `adb`): длина в 4 hex-цифрах + запрос, ответ `OKAY`/`FAIL`. Расширение открывает TCP-соединение (`Network.framework`, право `com.apple.security.network.client`), выбирает устройство (`host:transport:<serial>`) и дальше:
- `sync:` — `LIST`/`LIS2` (список папки), `STAT`/`STA2`, `RECV`/`RCV2` (скачать), `SEND`/`SND2` (отправить). Версии `*2` (64-битные размеры, нужны для файлов больше 4 ГБ) — когда устройство сообщает фичу `ls_v2`/`stat_v2` в `host-serial:<s>:features`.
- `shell:` — `mkdir -p`, `mv`, `rm -rf` с аргументами в одинарных кавычках (экранирование — функция в `UniversalKMCore` с тестами).

Кодирование и разбор пакетов (запросы, `DENT`/`DNT2`, `DATA`/`DONE`/`FAIL`, `OKAY`) — чистые функции в `UniversalKMCore`, ввод-вывод — в расширении.
*Альтернативы:*
- XPC к приложению, которое запускает `adb`. Тогда файлы есть только при запущенном приложении, и нужен канал: приложение открывает связь с расширением (`NSFileProviderServiceSource`) и передаёт ему свой анонимный `NSXPCListenerEndpoint`. Сложнее и хуже для пользователя.
- Положить `adb` в бандл расширения. Свой `adb` другой версии конфликтует с сервером пользователя (решение транспорта D5 — один общий сервер).

`127.0.0.1` — не локальная сеть, запроса macOS нет; с телефоном говорит сервер `adb` со своим разрешением.

### D3. Домен = устройство, идентификатор домена = серийный номер
Приложение регистрирует один `NSFileProviderDomain` на Android-устройство схемы, у которого есть ключ в `AndroidPeerRegistry`, кроме ключей `usb-loc:` (устройство без серийного номера, `adb` его не знает). `identifier` = серийный номер, `displayName` = имя устройства в схеме. Сверка при старте и после каждого изменения схемы: лишние домены удаляются, новые добавляются, переименованные — пересоздаются с тем же идентификатором.

Расширение по идентификатору домена находит текущий транспорт: `host:devices` → для каждого устройства в состоянии `device` — совпадение serial напрямую (USB), по имени mDNS `adb-<serial>-…` или, для `ip:port`, по `getprop ro.serialno` (результат запоминается до смены списка). Если устройство есть и по USB, и по Wi‑Fi — берётся USB: быстрее.

### D4. Идентификатор файла = путь от `/sdcard`
`NSFileProviderItemIdentifier` = путь (корень — `.rootContainer` = `/sdcard`). Стабильных номеров файлов на общей памяти Android нет (FUSE/sdcardfs). Версия содержимого = размер + время изменения, версия метаданных = имя + время изменения.
Переименование и перемещение: `mv`, затем `modifyItem` возвращает элемент с новым путём, а у старого и нового родителя вызывается `signalEnumerator`, чтобы система увидела удаление старого и появление нового. Проверяется в задаче 1.

### D5. Отправка через временное имя
`SEND` пишет в `<папка>/.<имя>.ukm-part`, после `DONE`/`OKAY` — `mv` на настоящее имя. Обрыв посреди отправки оставляет только скрытый временный файл (спецификация: «Связь пропала во время копирования»); такие файлы расширение не показывает и удаляет при следующей отправке в ту же папку. Скачивание пишет во временный файл, который даёт система, — там частичный файл не виден.

### D6. Изменения на устройстве
Уведомлений об изменениях `adb` не даёт. `enumerateChanges` для рабочего набора заново читает папки, которые Finder перечислял, и сравнивает со списком, сохранённым в якоре (`NSFileProviderSyncAnchor` — хэш списка). Приложение, пока запущено и устройство в состоянии `device`, раз в 30 секунд вызывает `signalEnumerator(for: .workingSet)` для домена устройства. Без приложения — при следующем перечислении папки (так в спецификации).

### D7. Подпись и группа приложений — проверяется первым
Группа приложений нужна для `NSExtensionFileProviderDocumentGroup`, а её идентификатор на macOS начинается с Team ID. Порядок:
1. Пробная сборка (задача 1.1) с самоподписанным сертификатом: загружает ли `fileproviderd` расширение, появляется ли место в Finder, нет ли запроса «доступ к данным других приложений».
2. Если нет — та же сборка с сертификатом Apple Development/Developer ID (`TEAMID.com.universalkm.files`).
3. Если работает только с сертификатом Apple — решение за владельцем: покупать Apple Developer ($99/год) и переходить на Developer ID с нотаризацией, или остановить изменение и сделать своё окно (D1, запасной вариант). Переход на Developer ID один раз сбросит разрешения «Универсальный доступ» и «Мониторинг ввода» (README, «Подпись»).

### D8. Сборка расширения из SwiftPM
SwiftPM не умеет `.appex`. Цель `UniversalKMFiles` — `executableTarget` с флагами компоновщика `-e _NSExtensionMain` и `-fapplication-extension` (`unsafeFlags`, допустимы в корневом пакете), зависит от `UniversalKMCore`. `scripts/build-app.sh` собирает `Contents/PlugIns/UniversalKMFiles.appex/Contents/{MacOS,Info.plist}` (`NSExtensionPointIdentifier` = `com.apple.fileprovider-nonui`, `NSExtensionPrincipalClass`, `NSExtensionFileProviderDocumentGroup`), подписывает его с `Resources/UniversalKMFiles.entitlements` (песочница, `network.client`, группа) до подписи приложения. Приложению добавляется только право группы; песочница у приложения не появляется.

### D9. Удаление без корзины
У элементов нет `allowsTrashing`, есть `allowsDeleting`: Finder сам предупреждает, что файл удалится сразу (спецификация: «Удалить файл»). `deleteItem` → `rm -rf` по пути.

### D10. Ошибки
Нет сервера или устройства → `NSFileProviderError(.serverUnreachable)` с текстом «Устройство не подключено»; система повторяет запрос, когда домен снова сигналят (приложение сигналит при появлении устройства в `track-devices`). `FAIL` от `adb` с «Permission denied» при перечислении → пустая папка без ошибки; при записи → `CocoaError(.fileWriteNoPermission)` (не `.notAuthenticated`: Finder понял бы его как просьбу войти в учётную запись).

## Risks / Trade-offs

- [macOS не загружает расширение с самоподписанным сертификатом] → проверка первой задачей (D7); запасной вариант — своё окно.
- [Путь как идентификатор: переименование видится системе как удаление + создание, может сбросить загруженные копии] → допустимо для телефона; проверка в задаче 1.
- [Скорость по Wi‑Fi] → USB предпочитается, когда есть (D3); в README честно про скорость.
- [`fileproviderd` держит расширение и кэш между запусками; после ошибок домен может «залипнуть»] → удалить и снова добавить устройство в схеме пересоздаёт домен; для отладки — `fileproviderctl` (README).
- [Имена файлов: Android допускает символы, которые Finder показывает по-другому (`:`)] → путь хранится как есть, отображаемое имя — как даёт Finder; проверка с файлом `a:b.txt`.
- [Сервер `adb` старой версии без `ls_v2`] → откат на `LIST`/`RECV`/`SEND`, файлы больше 4 ГБ тогда показываются с неверным размером — помечено в README.

## Migration Plan

Новая возможность, данных для переноса нет. Первый запуск новой версии регистрирует домены для уже известных устройств.

Откат на предыдущую версию: она о доменах не знает и убрать их не может, а без расширения Finder показывает их как недоступные. Удалять домены при выходе из приложения нельзя — тогда файлов не будет при закрытой панели (спецификация «Работа без открытой панели»). Поэтому после отката домены убираются командой из README (`fileproviderctl domain remove`) или исчезают вместе с удалённым приложением.
