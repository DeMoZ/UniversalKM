# Proposal

## Why

Чтобы взять фото с телефона или положить на него файл, сейчас нужен кабель и Android File Transfer или `adb push/pull` в Терминале. UniversalKM уже держит связь с телефоном через `adb`, по Wi‑Fi и по USB. По этой же связи можно открыть память телефона прямо в Finder.

## What Changes

- **Кнопка «Открыть в Finder»** в панели. Она видна, когда выбранное устройство — Android, к которому сейчас есть связь через `adb` (по Wi‑Fi или по USB с отладкой). Кнопка открывает окно Finder с памятью этого устройства.
- **Устройство в боковой панели Finder**, раздел «Места», под именем устройства (например, «Galaxy S10e»). Работает всё, что обычно умеет Finder: перетаскивание и копирование в обе стороны, создание папок, переименование, удаление (в корзину Mac не попадает, см. спецификацию), Quick Look. Файл скачивается с телефона, только когда его открывают или копируют.
- **Видна общая память** (`/sdcard`: DCIM, Download, Documents, Pictures, Music, Movies…). Личные данные приложений и системные папки не видны: `adb` без root туда не пускает.
- **Нет связи — нет доступа.** Если устройство не подключено через `adb`, Finder показывает его, но открыть папку нельзя: сообщение «Устройство не подключено». Как только связь вернулась, всё работает снова, без перезапуска.
- **Новый компонент приложения:** расширение File Provider (`UniversalKMFiles.appex`) внутри `UniversalKM.app`. Расширение говорит с сервером `adb` напрямую по `127.0.0.1:5037` (протокол sync), поэтому работает и когда сама панель UniversalKM закрыта, если сервер `adb` работает.
- **Решение по подписи (риск, проверяется первым).** Расширение File Provider должно жить в песочнице, а macOS может отказаться загружать его с самоподписанным сертификатом проекта. Если первая проверка (задача 1) это подтвердит, нужен сертификат Apple Developer ID; без него изменение останавливается, и мы возвращаемся к своему окну с файлами.

Вне этого изменения: устройства только по USB в режиме AOA без отладки (там нет `adb`, а MTP недоступен, пока телефон работает как аксессуар), Chameleon и iPhone/iPad, синхронизация папок, работа без связи (кэш правок, которые применятся позже).

## Capabilities

### New Capabilities

- `android-files`: память Android-устройства в Finder через `adb`: какие устройства видны и когда, что показывается, какие операции с файлами поддерживаются, что видит пользователь без связи и при ошибках.

### Modified Capabilities

(нет)

## Impact

- **Новый код:** цель SwiftPM `UniversalKMFiles` (расширение, `NSFileProviderReplicatedExtension`), клиент протокола `adb` (host и sync: `LIST`/`STAT`/`RECV`/`SEND`, `shell:` для `mkdir`, `mv`, `rm`) — разбор протокола в `UniversalKMCore`, чтобы его покрыли тесты.
- **Приложение:** регистрирует и убирает домены File Provider (`NSFileProviderManager`) для устройств, кнопка в `MenuBarView.swift`, строки перевода на 10 языков.
- **Сборка:** `scripts/build-app.sh` собирает `.appex` в `Contents/PlugIns/`, со своим `Info.plist` и правами (песочница, `network.client`), подписывает его до приложения. Релизный workflow — то же.
- **Подпись:** возможно, нужен Apple Developer ID (см. риск выше). Это может поменять подпись релизов: разрешения «Универсальный доступ» и «Мониторинг ввода» один раз попросятся заново.
- **Разрешения macOS:** новых запросов нет. `127.0.0.1` — не локальная сеть; связь с телефоном держит сервер `adb` со своим разрешением (fix-adb-server-local-network).
- **Скорость:** по Wi‑Fi несколько МБ/с, иногда десятки; по USB быстрее. Большие видео по Wi‑Fi копируются долго — это не ошибка.
