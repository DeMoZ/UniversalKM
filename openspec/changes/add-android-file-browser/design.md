# Design

## Context

Зачем и что — proposal.md, поведение — specs/android-file-browser/spec.md.

Что есть сейчас:
- `ADBClient` находит пользовательский `adb`, поднимает сервер (`ensureServer`, fix-adb-server-local-network D1) и следит за списком через `track-devices`. Команды — запуск процесса `adb`.
- `AndroidHIDTransport` знает для каждого Android-устройства (ключ — `ro.serialno`) его транспорты `adb` (`adbDevices`, `candidates`) и публикует `AndroidStatus.devices` (`AndroidDeviceStatus`: `peerID`, `name`, `serial`, `hasWiFi`, `hasADBOverUSB`…). Панель связывает `PlacedDevice.hostPeerID` с этим статусом.
- Приложение без песочницы, меню-бар (`LSUIElement`), панель на SwiftUI.

## Goals / Non-Goals

**Goals:** окно, которое не зависает на медленном Wi‑Fi; перенос с ходом и отменой; разбор протокола в `UniversalKMCore` с тестами на записанных ответах.

**Non-Goals:** File Provider и место в Finder (proposal, Why); свой `adb`; MTP; доступ при закрытом приложении.

## Decisions

### D1. Свой клиент протокола `adb` по `127.0.0.1:5037`, а не процессы `adb ls/pull/push`
Протокол хоста открыт (`OVERVIEW.TXT`, `SERVICES.TXT`, `SYNC.TXT` в исходниках `adb`): 4 hex-цифры длины + запрос, ответ `OKAY` или `FAIL` + 4 hex-цифры + текст. После `host:transport:<serial>` соединение идёт к устройству:
- `sync:` — `LIST`/`LIS2` (папка: режим, размер, время, имя), `STAT`/`STA2`, `RECV` (скачать: `DATA` + длина + данные…, `DONE`), `SEND` (`<путь>,<режим>`, затем `DATA`…, `DONE` + время, ответ `OKAY`/`FAIL`). `LIS2` (64-битные размеры) — если `host-serial:<s>:features` содержит `ls_v2`, иначе `LIST`.
- `shell:<команда>; printf '\nUKM_RC=%d\n' $?` — `mkdir -p`, `mv`, `rm -rf`; код выхода берётся из последней строки (у старого `shell:` своего кода нет), `$?` подставляется до запуска `printf`, а перевод строки перед маркером отделяет вывод без перевода строки.

Ход переноса — из числа байт `DATA`, отмена — закрытие сокета. `adb pull/push` из процесса этого не дают (ход печатается только в терминал), а разбор `ls -la` зависит от версии `toybox`.
Ввод-вывод — блокирующие сокеты POSIX на отдельных потоках (`ADBSocket`: `connect`, `writeAll`, `readExactly`, `close` из другого потока прерывает чтение). Кодирование и потоковый разбор — чистые функции в `UniversalKMCore` (`ADBProtocol`, `ADBSync`), разборщик принимает данные кусками любой длины.
*Альтернатива:* `Network.framework` — асинхронный, но протокол по сути последовательный, и блокирующий код проще читать и тестировать.

### D2. Какой транспорт берётся для файлов
`AndroidDeviceStatus` получает `fileTransport: String?` — serial транспорта `adb` в состоянии `device` и не из `deadTransports`: сначала `adb` по кабелю (быстрее), потом Wi‑Fi. Он же решает, есть ли кнопка «Файлы…». Окно следит за статусом: `fileTransport` сменился — открытая папка читается заново через новый транспорт; стал `nil` — «Устройство не подключено». Перенос, начатый на старом транспорте, не переносится на новый: он завершается ошибкой, если старый пропал.

### D3. Пути и корень
Корень — `/sdcard`. Путь — массив компонентов (`RemotePath` в `UniversalKMCore`: `appending`, `parent`, `string`, отображение «DCIM › Camera»). Выше корня подняться нельзя. Файлы `.*.ukm-part` (D5) в списке не показываются.

### D4. Окно: SwiftUI с таблицей на AppKit
`FileBrowserWindowController` (один на устройство, словарь по ключу устройства в `AppStateManager`) держит `NSWindow` с `NSHostingView`. Панель инструментов, путь, строка «Устройство не подключено», список переносов — SwiftUI. Сам список — `NSTableView` в `NSViewRepresentable`, потому что SwiftUI на macOS 14 не даёт надёжно:
- перетаскивание в Finder как обещание файла (`NSFilePromiseProvider`; для папки тип `public.folder`, `writePromiseTo` скачивает её целиком);
- приём файлов из Finder (`registerForDraggedTypes([.fileURL])`) и подсветку цели;
- множественный выбор, ⌘V, Delete, двойной щелчок, контекстное меню.

Модель — `FileBrowserModel` (`@MainActor`, `ObservableObject`): путь, список, история «Назад», состояние связи, переносы. Обновление (спецификация «Обновление списка») — таймер на 10 секунд, пока `window.occlusionState` содержит `.visible`.

### D5. Перенос без обрезанных файлов
- **Отправка:** `SEND` в `<папка>/.<имя>.ukm-part`, после `OKAY` — `mv -f` на настоящее имя. Отмена или обрыв → `rm -f` временного файла (если связь ещё есть). Оставшиеся `.ukm-part` не видны и удаляются при следующей отправке в ту же папку (`rm -f` по маске перед отправкой).
- **Скачивание:** в `<папка на Mac>/.<имя>.ukm-part`, по `DONE` — переименование в свободное имя (`уникальное имя` в `UniversalKMCore`: «фото.jpg» → «фото 2.jpg», как Finder). Отмена или обрыв — временный файл удаляется. Для перетаскивания в Finder папку назначения даёт `NSFilePromiseProvider`, правило то же.
- **Папки:** скачивание — обход `LIST` в глубину, папки создаются сразу, файлы по одному. Отправка — `mkdir -p` и файлы по одному.
- Переносы одного окна идут по очереди (один `sync:` за раз), список папки читается своим соединением, чтобы окно не ждало перенос.

### D6. Конфликт имён при отправке
Перед отправкой — список целевой папки (уже есть в модели, перечитывается). Для совпавших имён — один вопрос `NSAlert` на всю операцию: «Заменить», «Пропустить», галочка «Для всех». Заменить = отправка во временное имя, `mv -f`.

### D7. Ошибки
`FAIL` при `LIST` с «Permission denied» или «No such file» для вложенной папки → пустой список без ошибки (спецификация «Недоступная папка»). Нет сервера `adb` (connect refused) или устройства (`FAIL device '…' not found`) → состояние «Устройство не подключено». Ошибки переноса показываются в строке переноса текстом из `FAIL` или «Связь с устройством потеряна» при обрыве сокета.

### D8. Открытие файла
Двойной щелчок — скачивание в `FileManager.default.temporaryDirectory/UniversalKM/<serial>/<путь>` и `NSWorkspace.open`. Временная папка очищается при выходе из приложения.

## Risks / Trade-offs

- [Протокол `adb` меняется между версиями] → используем старые, всегда поддерживаемые запросы (`LIST`, `RECV`, `SEND`, `shell:`), `LIS2` только по признаку `ls_v2`; фикстуры записаны с реальных телефонов (Android 12 и 16) по тестовой папке.
- [Старый `shell:` без кода выхода, `echo UKM_RC=$?` попадёт в имя файла] → имена всегда в одинарных кавычках (экранирование с тестами), `UKM_RC` ищется только в последней строке.
- [Перетаскивание большой папки в Finder: Finder ждёт обещание без своего хода] → ход видно в окне; Finder показывает файл после переименования.
- [Скорость по Wi‑Fi] → кабель с отладкой предпочитается (D2); в README честно про скорость.
- [Имена с `:` и другими символами, которые Finder показывает по-своему] → на Mac имя сохраняется как есть, Finder сам покажет `:` как `/`; проверка с `a:b.txt`.

## Migration Plan

Новая возможность, данных для переноса нет. Откат — предыдущая версия без кнопки; на телефоне могут остаться только скрытые `.ukm-part` после обрыва.
