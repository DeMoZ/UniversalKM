# Design

## Context

Связь с телефоном — `adb` (USB или Wi‑Fi), его уже использует приложение. Захват экрана Android без согласия на экране разрешён только uid `shell`; так работает scrcpy: Java-сервер через `app_process` с `CLASSPATH`, скрытые API `DisplayManager`/`SurfaceControl` и `InputManager.injectInputEvent`. Эти API меняются от версии к версии Android, и scrcpy их поддерживает.

## Goals / Non-Goals

Цели: экран телефона на Mac с задержкой как у scrcpy (< 100 мс по Wi‑Fi в одной сети), касания и прокрутка, навигация, ввод текста; ничего не ставить на телефон. Не цели: звук, запись, своя реализация захвата.

## Decisions

### D1. Готовый scrcpy-server, а не свой
Сервер — неизменённый `scrcpy-server-v5.0.1` из релиза Genymobile/scrcpy (Apache‑2.0), SHA‑256 `764eb6f7…bc536`, в `Resources/scrcpy-server.jar`; `scripts/fetch-scrcpy-server.sh` скачивает его и проверяет сумму. Своя реализация повторила бы обёртки скрытых API для Android 9–16 и их обходы для прошивок — это большая и хрупкая часть scrcpy. Клиент (протокол, окно) свой, на Swift: бинарник scrcpy и SDL не нужны.
*Альтернативы:* `screenrecord` + `input tap` (screenrecord обрывается через 3 минуты, `input` — новый процесс на каждое касание, 0.3–0.5 с); свой сервер в APK камеры (см. выше); бинарник scrcpy (отдельное окно, свои клавиши, ещё ≈12 МБ).

### D2. Запуск и связь
Файл кладётся в `/data/local/tmp/ukm-scrcpy-server-5.0.1.jar`, если его там нет (`ls`, затем `push`). Процесс `adb -s <t> shell CLASSPATH=… app_process / com.genymobile.scrcpy.Server 5.0.1 scid=<8 hex> audio=false control=true tunnel_forward=true send_device_meta=false clipboard_autosync=false max_size=1920 log_level=info` живёт, пока открыто окно. `adb forward tcp:0 localabstract:scrcpy_<scid>`; первое соединение — видео (ждём байт 0: пока сервер не слушает, adb принимает соединение и сразу закрывает — тогда повтор раз в 0.3 с, 10 с), второе — управление. `clipboard_autosync=false`: буфер обмена ведёт свой помощник (add-android-clipboard-sync). Закрытие окна: соединения закрываются (сервер сам выходит, `cleanup=true` возвращает настройки телефона), процесс `adb shell` завершается, `forward` снимается. Версия сервера и строка версии в аргументах — одна константа: сервер не запускается с другой версией клиента.

### D3. Поток видео
После байта 0: `u32` кодек (`h264`; 0 или 1 — сервер отключил видео, окно показывает ошибку из журнала сервера), затем пакеты по 12 байт заголовка: старший бит — пакет сессии (ширина, высота; новая сессия при повороте), иначе флаги «настройка»/«ключевой», PTS и длина. Пакет настройки — SPS и PPS в Annex B → `CMVideoFormatDescription`; кадры → AVCC → `AVSampleBufferDisplayLayer` с `DisplayImmediately`, как в «Вживую» (add-android-motion-camera D11). Разбор — в `UniversalKMCore` с тестами.

### D4. Ввод
Точка в окне → пиксель кадра с учётом полей `resizeAspect`; вне картинки — не отправляется. Касание — сообщение `INJECT_TOUCH_EVENT` с указателем «мышь» (−1) и кнопкой «основная»: сервер делает из него касание (`SOURCE_TOUCHSCREEN`). В сообщении — размер кадра; сервер отбрасывает события для старого размера, поэтому после поворота события идут с новым. Прокрутка — `INJECT_SCROLL_EVENT`, колесо — по 1 на щелчок, трекпад — дельта / 10, предел ±16. Правая кнопка и Esc — `BACK_OR_SCREEN_ON` (ещё и будит экран). «Домой»/«Недавние» и Return, Delete, стрелки, Tab — `INJECT_KEYCODE` (нажатие и отпускание); остальной текст — `INJECT_TEXT`. Сочетания с ⌘ остаются Mac (⌘W закрывает окно).

### D5. Где кнопка
«Экран…» — в строке раздела «Камера движения» (там уже все Android-устройства с `adb`), доступна, пока есть `adb`; приложение камеры не нужно. В окне «Вживую» при «Камера не отвечает» — «Показать экран». Одно окно на устройство; Dock-значок — как у остальных окон.

## Risks / Trade-offs

- [Новая версия Android ломает скрытые API] → обновить сервер (поменять версию и сумму в одном месте, протокол сверить по `doc/develop.md` и тестам scrcpy).
- [Протокол scrcpy меняется между версиями] → версия зашита и проверяется сервером; тесты на разбор и сообщения.
- [Экран заблокирован/выключен] → `power_on=true` (по умолчанию) будит экран при запуске; блокировку снимает пользователь — касаниями в окне, если блокировка жестом/PIN.
- [Защищённые окна (банки, DRM)] → чёрные: так решает Android, не обходим.
