# Spec Delta

## Purpose

Определяет, как Mac передаёт мышь и клавиатуру на Android‑устройство без провода и без дополнительного железа: через ADB по Wi‑Fi и встроенную в Android поддержку виртуальных HID‑устройств. Здесь же — сопряжение, повторное подключение и переход одного телефона между USB и Wi‑Fi.

## ADDED Requirements

### Requirement: Программа adb
Для Wi‑Fi приложение SHALL использовать установленную у пользователя программу `adb` (Android platform‑tools) и находить её само в стандартных местах. Если `adb` не найден, Wi‑Fi SHALL быть недоступен, а панель SHALL показывать, как установить `adb`; USB и Chameleon при этом SHALL работать.

#### Scenario: adb не установлен
- **WHEN** на Mac нет `adb`
- **THEN** блок «Android по Wi‑Fi» в панели показывает подсказку по установке, а Android по USB работает

#### Scenario: adb установлен через Homebrew
- **WHEN** `adb` лежит в `/opt/homebrew/bin`, а приложение запущено из Finder (без PATH оболочки)
- **THEN** приложение находит `adb` и включает Wi‑Fi

### Requirement: Сопряжение по коду («Отладка по Wi‑Fi»)
Для Android 11 и новее панель SHALL позволять сопрячь телефон по адресу и коду из раздела «Отладка по Wi‑Fi» на телефоне. После сопряжения приложение SHALL само находить этот телефон в той же сети и подключаться к нему, в том числе после перезагрузки телефона и Mac, пока на телефоне включена «Отладка по Wi‑Fi».

#### Scenario: Первое сопряжение
- **WHEN** пользователь вводит в панели адрес и шестизначный код из окна «Сопряжение по коду» на телефоне
- **THEN** приложение сопрягается с телефоном, подключается к нему и предлагает добавить его в схему

#### Scenario: Неверный код
- **WHEN** пользователь вводит неверный код
- **THEN** панель показывает ошибку сопряжения, ничего не подключается

#### Scenario: Телефон перезагрузили
- **WHEN** сопряжённый телефон перезагружается и снова включает «Отладку по Wi‑Fi» в той же сети
- **THEN** приложение в течение 10 секунд подключается к нему без участия пользователя

### Requirement: Wi‑Fi через кабель (`adb tcpip`)
Для телефона, подключённого кабелем с включённой «Отладкой по USB», панель SHALL предлагать «Включить Wi‑Fi». Приложение SHALL переводить ADB телефона в режим TCP, запоминать его адрес в сети и подключаться по Wi‑Fi, а после отключения кабеля SHALL продолжать работу по Wi‑Fi. Приложение SHALL переподключаться по запомненному адресу, пока телефон не перезагружен.

#### Scenario: Включить Wi‑Fi и выдернуть кабель
- **WHEN** телефон с «Отладкой по USB» подключён кабелем, пользователь нажимает «Включить Wi‑Fi», а потом выдёргивает кабель
- **THEN** телефон остаётся подключённым, статус в панели — «Wi‑Fi», ввод продолжает работать

#### Scenario: Телефон перезагрузили после tcpip
- **WHEN** телефон, подключённый через `adb tcpip`, перезагружается
- **THEN** статус — «не подключено», а панель подсказывает подключить кабель и снова нажать «Включить Wi‑Fi»

### Requirement: Подключение только с согласия пользователя по Wi‑Fi
Приложение SHALL создавать клавиатуру и мышь на телефоне по Wi‑Fi только для устройств, добавленных в схему. Телефон, доступный по ADB, но не добавленный, SHALL появляться в панели как предложение «Добавить» и не получать HID.

#### Scenario: Телефон доступен по ADB, но не добавлен
- **WHEN** к приложению по ADB подключён телефон, которого нет в схеме
- **THEN** на телефоне не появляется физическая клавиатура, а панель предлагает добавить его

### Requirement: Доставка ввода по Wi‑Fi
Пока ввод передан телефону по Wi‑Fi, приложение SHALL доставлять ему движение мыши, кнопки, прокрутку и нажатия клавиш с модификаторами тем же составом отчётов, что по USB и через Chameleon. Отчёты клавиатуры SHALL не теряться и приходить по порядку; движение мыши может сливаться.

#### Scenario: Набор текста по Wi‑Fi
- **WHEN** телефон подключён только по Wi‑Fi, на нём открыто текстовое поле, и пользователь набирает «Hello 123»
- **THEN** в поле появляется «Hello 123» без пропущенных и лишних символов

#### Scenario: Курсор по Wi‑Fi
- **WHEN** ввод передан телефону по Wi‑Fi, и пользователь двигает мышь и щёлкает
- **THEN** на телефоне двигается курсор и срабатывает нажатие

### Requirement: Один телефон по USB и по Wi‑Fi
Телефон SHALL занимать одно место в схеме независимо от канала: приложение SHALL узнавать его по серийному номеру. Если доступны оба канала, приложение SHALL использовать USB. Когда пропадает текущий канал, а другой доступен, приложение SHALL переходить на другой без участия пользователя и без возврата курсора на Mac; клавиши и кнопки при переходе SHALL отпускаться.

#### Scenario: Кабель выдернули, Wi‑Fi есть
- **WHEN** телефон подключён по USB и по Wi‑Fi, ввод у него, и кабель выдёргивают
- **THEN** курсор остаётся на телефоне, ввод продолжает работать по Wi‑Fi, статус — «Wi‑Fi»

#### Scenario: Кабель вставили обратно
- **WHEN** телефон работает по Wi‑Fi, и его подключают кабелем
- **THEN** приложение переходит на USB, статус — «USB», на телефоне одна физическая клавиатура, а не две

### Requirement: Потеря Wi‑Fi
Когда телефон, подключённый только по Wi‑Fi, пропадает из сети (ADB‑соединение разорвано), приложение SHALL считать его отключённым и вернуть ввод на Mac, если ввод был у него; при появлении снова — подключаться без участия пользователя.

#### Scenario: Телефон ушёл из сети
- **WHEN** ввод передан телефону по Wi‑Fi, и на телефоне выключают Wi‑Fi
- **THEN** в течение 3 секунд курсор возвращается на Mac, статус — «не подключено»

### Requirement: Снятие клавиатуры по Wi‑Fi
Приложение SHALL удалять клавиатуру и мышь с телефона по Wi‑Fi, отпустив перед этим все клавиши и кнопки, когда устройство удаляют из схемы, когда приложение завершается и когда передачу выключают.

#### Scenario: Выход из приложения
- **WHEN** телефон подключён по Wi‑Fi и добавлен в схему, и пользователь выходит из приложения
- **THEN** на телефоне пропадает физическая клавиатура, и снова появляется экранная
