# Proposal

## Why

Сейчас UniversalKM работает только через ChameleonUltra с нашей прошивкой; без него передачи нет. Для Android это лишнее — проверено 2026‑11‑09 на Samsung S10e (Android 12):

- **По кабелю:** Mac становится для телефона обычной проводной клавиатурой и мышью по протоколу Android Open Accessory 2 (AOA2 HID) — без отладки по USB, root и приложения на телефоне.
- **По Wi‑Fi:** через ADB встроенная утилита Android `/system/bin/hid` создаёт на телефоне настоящую HID‑клавиатуру и мышь (UHID) с нашим дескриптором; задержка ADB по Wi‑Fi — медиана 8 мс туда‑обратно. Нужен включённый режим разработчика, но не нужно никакое железо.

Курсор двигался, текст набирался в обоих случаях. Так у Android появляются два основных способа без покупки и прошивки Chameleon; Chameleon остаётся для iPhone/iPad и для тех, кто не хочет включать отладку.

## What Changes

- **Новый транспорт Android (`AndroidHIDTransport`, реализация `HIDTransport`) с двумя каналами:**
  - **USB (AOA2 HID):** приложение само находит Android на USB, проверяет AOA ≥ 2, регистрирует составное HID‑устройство (клавиатура + мышь, тот же дескриптор, что у Chameleon) и шлёт отчёты управляющими запросами AOA.
  - **Wi‑Fi (ADB):** через установленный `adb` (Android platform‑tools) приложение держит `adb shell hid -` на телефоне и шлёт регистрацию и отчёты строками JSON. Подключение — «Отладка по Wi‑Fi» (Android 11+, сопряжение по коду из панели, дальше телефон находится в сети сам) или `adb tcpip` (любой Android; кабель один раз после перезагрузки телефона, кнопка в панели).
- **Один телефон — одно место в схеме при любом канале.** Телефон узнаётся по серийному номеру (USB‑серийный = `ro.serialno`); если доступны оба канала, используется USB; при выдёргивании кабеля работа продолжается по Wi‑Fi без участия пользователя, и обратно.
- **Два транспорта одновременно.** `CompositeHIDTransport` направляет отчёты Android‑транспорту или Chameleon по peer ID. Общий лимит в схеме — три устройства.
- **Порядок способов: Android по проводу и по Wi‑Fi — основные, Chameleon — дополнительный.** Приложение работает без Chameleon; его отсутствие не ошибка.
- **Чужой Android сам клавиатуру не получает.** Телефон, найденный по USB или ADB, но не добавленный в схему, не регистрируется как клавиатура (иначе пропадает экранная клавиатура) — панель предлагает его добавить. При выходе регистрация снимается.
- **Панель:** у устройства — «USB», «Wi‑Fi», «Bluetooth через Chameleon» или «не подключено»; блок «Android по Wi‑Fi» (сопряжение по коду, «Включить Wi‑Fi у телефона на кабеле», подсказка установить `adb`, если его нет); статус Chameleon — второй строкой.
- **Документация:** README.md и README.ru.md: первыми идут «Android по проводу» и «Android по Wi‑Fi (ADB)», затем блок «ChameleonUltra и похожие платы» (iPhone/iPad, без отладки, до трёх устройств), куда переезжает «почему не встроенный Bluetooth Mac». Уточняется фраза README о том, что libusb на macOS отказывает: отказ касается захвата интерфейса, управляющим запросам AOA захват не нужен.

## Capabilities

### New Capabilities

- `android-usb-link`: ввод Mac → Android по USB через AOA2 HID: поиск и проверка устройства, согласие пользователя, регистрация и снятие, доставка отчётов, отключение кабеля, работа рядом с Chameleon и без него, отображение в панели.
- `android-wifi-link`: ввод Mac → Android по Wi‑Fi через ADB и встроенный UHID: наличие `adb`, сопряжение и подключение («Отладка по Wi‑Fi», `adb tcpip`), повторное подключение, регистрация и доставка, переход между USB и Wi‑Fi для одного телефона.

### Modified Capabilities

(нет — в `openspec/specs/` ещё нет спецификаций. Конфликт с незаархивированным `add-ble-hid-input-bridge`: требование «Подключение ChameleonUltra по USB» (`ble-hid-peripheral`) говорит «передача на устройство недоступна» без Chameleon — теперь это относится только к устройствам через Chameleon; уточнение — в `android-usb-link`, «Работа без ChameleonUltra».)

## Impact

- **Приложение:** новые `AndroidHIDTransport.swift`, `AOALink.swift` + `AndroidUSBDeviceWatcher.swift` (USB), `ADBLink.swift` + `ADBClient.swift` (Wi‑Fi), `CompositeHIDTransport.swift`; правки `AppDelegate`, `AppStateManager`, `MenuBarView`, строк локализации.
- **Core:** `AOAHID.swift` (запросы и события AOA, признак Android), `HidCommand.swift` (JSON для `hid`), `AndroidPeerRegistry` (peer ID `0x8000…` по серийному номеру) — с unit‑тестами. Дескриптор и отчёты — из `HIDReportDescriptor`/`HIDReports`.
- **Зависимости:** USB — IOKit (`IOUSBDeviceInterface.DeviceRequest`), без сторонних библиотек (libusb — запасной путь, если IOKit не пропустит запросы). Wi‑Fi — внешняя программа `adb` пользователя (PATH, `/opt/homebrew/bin`, `~/Library/Android/sdk/platform-tools`); в приложение не встраивается.
- **Сохранённые данные:** peer ID Android‑устройств и последний адрес Wi‑Fi — в UserDefaults; схемы с Chameleon не меняются.
- **Разрешения macOS:** новых нет (может появиться запрос «Локальная сеть» для mDNS‑поиска телефонов — проверить в задачах).
- **Ограничения:** только Android; iOS/iPadOS не принимают HID от USB‑хоста и не дают ADB — для них Chameleon. Для Wi‑Fi нужен режим разработчика и `adb`. Встроенный Bluetooth Mac роли HID не имеет (проверено 2026‑11‑08).
