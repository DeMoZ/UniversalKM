# Proposal

## Why

Сейчас UniversalKM работает только через ChameleonUltra с нашей прошивкой: без него передача ввода недоступна вовсе. Для Android это лишнее. Проверка 2026‑11‑09 на Samsung (`04e8:6860`, AOA 2) показала, что Mac может стать для телефона обычной проводной клавиатурой и мышью по протоколу Android Open Accessory 2 (AOA2 HID): курсор двигался, текст набирался в Заметках. Для этого не нужны отладка по USB, root, приложение на телефоне и дополнительное железо: нужен только кабель. Так у Android-устройств появляется основной способ подключения, без покупки и прошивки Chameleon, а у курсора задержка меньше, чем по Bluetooth.

## What Changes

- **Новый транспорт `AndroidUSBTransport`** (реализация `HIDTransport`). Приложение само находит Android-устройства на USB и проверяет, что они поддерживают AOA версии 2 или выше. На устройстве, добавленном в схему, оно регистрирует составное HID-устройство: клавиатуру и мышь с тем же дескриптором отчётов, что у Chameleon. Отчёты оно шлёт управляющими USB-запросами AOA. Когда кабель вынимают, устройство считается отключённым; когда вставляют снова, приложение подключается само.
- **Два транспорта одновременно.** Новый маршрутизатор `CompositeHIDTransport` отправляет отчёты устройству через тот транспорт, к которому оно подключено: USB-Android или Chameleon. Общий лимит в схеме остаётся три устройства.
- **Android по проводу становится основным способом.** Приложение работает без Chameleon: если подключён хотя бы один Android по USB, передача доступна. Отсутствие Chameleon больше не ошибка, а просто незадействованный беспроводной способ.
- **Чужой Android не получает клавиатуру сам по себе.** Телефон, который просто воткнули зарядиться, не регистрируется как клавиатура: иначе на нём пропала бы экранная клавиатура. Приложение предлагает добавить его в панели, как сейчас делается с новыми Bluetooth-хостами. HID регистрируется только на устройствах из схемы, а при выходе из приложения регистрация снимается.
- **Панель:** у каждого устройства видно, как оно подключено («USB» или «Bluetooth через Chameleon»). Статус Chameleon уходит во второстепенную строку.
- **Документация:** README.md и README.ru.md перестраиваются. Первым идёт «Android по проводу» (без дополнительных устройств). Следом идёт «ChameleonUltra и похожие платы»: без провода, для iPhone и iPad, до трёх устройств. Туда же переезжает блок про встроенный Bluetooth Mac. Заодно исправляется утверждение README, что libusb на macOS отказывает всегда: отказ касается захвата интерфейса, а управляющим запросам к устройству, которые использует AOA, захват не нужен.

## Capabilities

### New Capabilities

- `android-usb-link`: передача ввода Mac на Android-устройство по USB через AOA2 HID. Сюда входят поиск и проверка устройства, регистрация и снятие HID, доставка отчётов, отключение и повторное подключение кабеля, согласие пользователя на подключение, работа рядом с Chameleon и без него, отображение в панели.

### Modified Capabilities

(нет: в `openspec/specs/` ещё нет спецификаций. Конфликт с незаархивированным `add-ble-hid-input-bridge` описан в `design.md` и снимается в `android-usb-link`. Требование «Подключение ChameleonUltra по USB» из `ble-hid-peripheral` гласит: «передача на устройство недоступна», пока нет Chameleon. Теперь это касается только устройств, подключённых через Chameleon.)

## Impact

- **Приложение:** новые `AndroidUSBTransport.swift`, `AndroidUSBDeviceWatcher.swift` и `CompositeHIDTransport.swift`. Также меняются `AppDelegate` (создание транспортов), `AppStateManager` (хосты двух транспортов, предложение добавить Android), `MenuBarView` (способ подключения у устройства, статус Chameleon вторым планом) и `TransportStatus`.
- **Core:** кодирование AOA-запросов и выдача ID для USB-хостов (`AOAHID.swift`) с unit-тестами. Дескриптор и отчёты переиспользуются из `HIDReportDescriptor` и `HIDReports`.
- **Зависимости:** работа с USB идёт через IOKit (`IOUSBLib`, `DeviceRequest` по нулевой конечной точке), сторонних зависимостей нет. Если окажется, что IOKit без захвата интерфейса этих запросов не пропускает, остаётся libusb (`libusb 1.0.27`, проверено). Это первая задача, и её результат записывается в `design.md`.
- **Сохранённые данные:** `hostPeerID` у USB-устройств берётся из отдельного диапазона (`0x8000…`) и связан с серийным номером USB в UserDefaults. Существующие схемы с Chameleon не меняются.
- **Разрешения:** новых нет. Accessibility и Input Monitoring уже есть, а USB-доступ к устройству разрешений не требует.
- **Ограничения:** только Android. iOS и iPadOS не принимают HID от USB-хоста, для них остаётся Chameleon. Нужен кабель с передачей данных. Без провода Android-устройство управляется только через Chameleon, у встроенного Bluetooth Mac роли HID нет (проверено 2026‑11‑08).
