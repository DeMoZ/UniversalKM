# Design

## Context

Зачем — proposal.md, раздел «Why». Требования — `specs/android-motion-camera/spec.md`.

Что есть сейчас (по коду, main 9976289):

- `ADBClient` находит `adb` пользователя и запускает команды (`run(_:timeout:on:completion:)`), `AndroidDeviceStatus.fileTransport` даёт `adb`-транспорт устройства (кабель с отладкой, потом Wi‑Fi). На него опирается окно файлов (`FileBrowsers.show(key:name:transport:)`, `FileBrowserModel` с `path: RemotePath`).
- В панели (`MenuBarView.swift`) есть раздел «Files and Photos» с кнопкой «Files…» у Android-устройств с `fileTransport`.
- На телефоне до сих пор ничего не ставилось. Это первое приложение UniversalKM на Android.
- На Mac владельца есть Android SDK (`~/Library/Android/sdk`: build-tools с `aapt2`, `d8`, `zipalign`, `apksigner`; platform android‑34) и `javac`. Устройства: S10e (Android 12, sdk 31), SM‑X115 (Android 16, sdk 36).

Ограничения Android, которые определяют решение:
- Камера в фоне — только из foreground-сервиса с типом `camera` (Android 14+: ещё разрешение `FOREGROUND_SERVICE_CAMERA`). Такой сервис нельзя запустить из фона (ограничение «while-in-use»): с Android 14 — и из `BOOT_COMPLETED`. Его можно запустить из видимой Activity.
- Фоновый запуск Activity запрещён, кроме исключений; одно из них — разрешение «поверх окон» (`SYSTEM_ALERT_WINDOW`), которое `adb` выдаёт через `appops`. `am start` из `adb shell` Activity запускает всегда.
- С Android 10 своё видео в `Movies/…` пишется через `MediaStore` без разрешений на память.

## Goals / Non-Goals

**Goals:**
- Камера работает сутками без Mac, переживает сон экрана, Doze и перезагрузку.
- Установка и настройка — с Mac, без нажатий на телефоне, где Android это позволяет.
- Сборка UniversalKM без Android SDK; APK — готовый файл в репозитории.

**Non-Goals:**
- AndroidX, Gradle, Kotlin: приложение маленькое, на чистом Android API.
- Свой интерфейс настроек на телефоне: там только выключатель и состояние.
- Связь камеры с Mac помимо `adb` (сеть, сокеты): приложение без `INTERNET`.

## Decisions

### D1. APK на Java без Gradle, пакет `com.universalkm.motion`
Исходник — `android/motion-camera/` (`AndroidManifest.xml`, `res/`, `src/com/universalkm/motion/*.java`). `scripts/build-motion-apk.sh`: `aapt2 compile` + `aapt2 link` против `android-34/android.jar` → `javac --release 11` → `d8 --min-api 31` → `zipalign` → `apksigner` → `Resources/ukm-motion.apk`. `minSdk 31` (Android 12): ниже Camera2 и FGS ведут себя иначе, а оба устройства владельца ≥ 31. `targetSdk 34`. `versionCode` растёт с каждой правкой; Mac сравнивает его с установленным (D6). `build-app.sh` только копирует APK в `Contents/Resources`.
*Альтернативы:* Gradle + AndroidX (тяжёлая сборка, зависимости ради маленького приложения); собирать при каждой сборке приложения (всем сборщикам нужен SDK).

### D2. Ключ подписи
Ключ — `~/.config/universalkm/motion-release.keystore` владельца (PKCS12, alias `ukm-motion`), в репозиторий не попадает. Пароль — в файле `motion-release.pass` рядом (права 600); `keytool` и `apksigner` читают его из файла (`-storepass:file`, `--ks-pass file:`), так что он не появляется ни в аргументах, ни в выводе. Пути можно переопределить через `UKM_MOTION_KEYSTORE` / `UKM_MOTION_KEYSTORE_PASS_FILE`. В репозитории — уже подписанный APK. `adb install -r` ставит обновление только с тем же ключом, поэтому ключ один на всё время жизни приложения; потеря ключа = удалить приложение на телефоне и поставить заново (записи в `Movies` остаются). В README — как сделать резервную копию ключа.
*Альтернатива:* отладочный ключ в репозитории (кто угодно с ним мог бы подменить приложение тем, у кого есть `adb` к телефону; риск мал, но держать приватный ключ в репо незачем).

### D3. Запуск камеры: невидимая `ControlActivity` → `MotionService`
- `MotionService` — foreground-сервис `foregroundServiceType="camera"` с постоянным уведомлением («Камера движения: ждёт движения / пишет», действие «Выключить»). Держит `PARTIAL_WAKE_LOCK`, пока включён.
- `ControlActivity` — прозрачная, без интерфейса, `exported` с `android:permission="android.permission.DUMP"` (D5). Принимает extras (`on`, настройки), сохраняет их в `SharedPreferences`, при `on=true` вызывает `startForegroundService` (она видима — запуск разрешён) и сразу `finish()`.
- `MainActivity` — то, что открывается иконкой: выключатель и строка состояния.
- После перезагрузки: `BootReceiver` (`BOOT_COMPLETED`, `MY_PACKAGE_REPLACED`) при включённой камере запускает `ControlActivity` (исключение для фонового запуска — разрешение «поверх окон», D6). Если запуск не прошёл (`startActivity` бросил исключение или сервис не поднялся за 10 с), показывается уведомление «Включить камеру» с `PendingIntent` на `ControlActivity` — нажатие на уведомление разрешает запуск всегда.
- Батарея: при ≤ 10 % без зарядки сервис закрывает ролик и останавливает камеру, но не себя; по `ACTION_POWER_CONNECTED` продолжает. Так не нужен повторный запуск FGS из фона.
*Альтернативы:* запуск сервиса из `BroadcastReceiver` по `am broadcast` (запрещено «while-in-use» на Android 14+); помощник `app_process` (не живёт без `adb`, решение владельца 2026‑11‑10).
*Проверить на устройствах первым (задача 1.1):* камера в FGS при выключенном экране и в Doze на S10e и SM‑X115; запуск после перезагрузки через «поверх окон» на Android 16 (в Android 15 исключения для FGS ужесточили; для Activity — нужно проверить).

### D4. Камера, поиск движения, запись
Камера через Camera2 с двумя выходами одной сессии:
1. `ImageReader` YUV_420_888 320×240 — для поиска движения;
2. входная `Surface` кодера `MediaCodec` H.264 (720p по умолчанию, 1080p по настройке, 30 к/с, ключевой кадр раз в 1 с, битрейт 4 / 8 Мбит/с).

**Поиск движения** (класс `MotionDetector`, чистая Java без Android API — тестируется на JVM): 5 кадров в секунду, канал Y уменьшается до 80×60 усреднением блоков. Сначала вычитается общий сдвиг яркости кадра относительно фона (автоэкспозиция). Точка «изменилась», если `|y − bg − сдвиг| > 20`. Фон — скользящее среднее: спокойные точки подтягиваются на 1/8 за кадр, изменившиеся — на 1/64. Так прохожий не оставляет «призрака» (фон под ним не успел измениться), а оставленная вещь растворяется примерно за 20 с. Кадр «с движением», если изменилось больше порога: 2 % / 0.7 % / 0.25 % точек (чувствительность низкая/средняя/высокая), два кадра подряд. Если изменилось больше 60 % — это смена освещения: фон сразу заменяется текущим кадром, кадр не считается движением (требование про свет).

**Часы.** Камера ставит меткам изображений `elapsedRealtime` (`SENSOR_INFO_TIMESTAMP_SOURCE_REALTIME`), а меткам выхода в видеокодер — монотонные часы, даже на одной сессии (проверено на SM‑X115: «images realtime, encoder monotonic», разница ≈ 7 дней сна). Поэтому часы каждого источника определяются по первому кадру (ближе к `System.nanoTime` или к `elapsedRealtimeNanos`), и всё переводится на монотонные. От них же считается время начала ролика для имени файла.

**Разогрев.** Первые 2 с после открытия камеры фон детектора начинается заново с каждого кадра: экспозиция и фокус ещё подстраиваются.

**Предзапись**: кодер работает всегда. Закодированные кадры (байты + время + флаг ключевого) лежат в кольцевом буфере на 3 с + 1 с запаса (≈ 2–4 МБ). Когда начинается движение, открывается новый файл (`FragmentedMp4Writer`, ниже) и в него пишется буфер начиная с ключевого кадра, который не позже чем за 3 с до движения, дальше — кадры по мере кодирования. Без звука — одна дорожка.

**Конец ролика**: через «задержку остановки» без движения; через 10 минут — закрыть файл и сразу начать новый со следующего ключевого кадра (кадры не теряются: следующий ключевой кадр через ≤ 1 с, а кадры до него остаются в старом файле).

**Устойчивость к обрыву питания — свой фрагментированный MP4.** `MediaMuxer` пишет `moov` только при закрытии, поэтому оборванный файл не проигрывается, а фрагментированного режима у него нет. Поэтому ролик пишет свой `FragmentedMp4Writer` (чистая Java, тестируется на JVM): `ftyp` + `moov` с `avcC` из SPS/PPS кодера (`mvex`/`trex`), потом каждую секунду (на каждом ключевом кадре) `moof` + `mdat`, после каждого фрагмента — `flush`/`fsync`. Оборванный файл проигрывается до последнего записанного фрагмента (≤ 1 с потерь). QuickTime/AVFoundation и галерея Android такие файлы открывают; проверка — задача 2.3.
*Альтернативы:* `MediaMuxer` + новый файл каждые 60 с (до минуты потерь и десятки файлов на одно событие — противоречит сценарию «Долгое движение»); `MediaRecorder` (не умеет предзапись — начинает только с момента старта); OpenCV (большая зависимость).

### D5. Управление с Mac: `am start` и `content query`, защита `DUMP`
- Команды: `adb shell am start -n com.universalkm.motion/.ControlActivity --ez on true --es sens mid --ei stop 10 --es cam back --es q 720 --el limitMB 4096`. Набор ключей строит `MotionCommand` в `UniversalKMCore` (экранирование как в `ADBShell`).
- Состояние: `MotionStatusProvider` (`ContentProvider`, `readPermission="android.permission.DUMP"`). `adb shell content query --uri content://com.universalkm.motion/status` → одна строка `Row: 0 state=watching, on=1, clips=12, bytes=…, free=…, battery=…, charging=1, version=3, settings=…`. Разбор — `MotionStatus.parse` в `UniversalKMCore`, тесты на фикстурах с обоих устройств.
- `DUMP` — разрешение уровня `signature|privileged|development`: у пользователя `shell` (`adb`) оно есть, у сторонних приложений — нет. Так выполняется требование «только через `adb`».
- Mac опрашивает состояние раз в 5 с, пока панель открыта и выбрано это устройство; иначе — не опрашивает.
*Альтернативы:* `am broadcast` с результатом (`setResultData`) — работает для состояния, но команда «включить» всё равно требует Activity (D3); один `ContentProvider.call` для всего — тоже не может запустить FGS из фона. Свой сокет через `adb forward` — нужен `INTERNET`.

### D6. Установка и разрешения с Mac
`MotionCameraClient` (приложение, поверх `ADBClient.run`):
1. версия: `adb shell pm list packages --show-versioncode com.universalkm.motion` → нет / `versionCode`; сравнение с `versionCode` APK в Resources (записан в `Resources/ukm-motion.version` скриптом сборки, чтобы не разбирать APK на Mac);
2. `adb install -r -g <apk>` (таймаут 120 с) — `-g` выдаёт камеру и уведомления;
3. `adb shell appops set com.universalkm.motion SYSTEM_ALERT_WINDOW allow`;
4. `adb shell dumpsys deviceidle whitelist +com.universalkm.motion` и `cmd appops set com.universalkm.motion RUN_ANY_IN_BACKGROUND allow` (Samsung без этого усыпляет фоновые приложения).
Шаги 3–4 повторяются при каждом включении с Mac (дёшево; пользователь мог снять в настройках). Ошибка `INSTALL_FAILED_USER_RESTRICTED` (Xiaomi, некоторые Samsung — «Установка через USB») → панель пишет, что подтвердить на телефоне.

### D7. Хранение и уборка
`MediaStore.Video.Media` с `RELATIVE_PATH = "Movies/UniversalKM Motion/"`. Пока ролик пишется, он называется `2026-11-10_14-32-05 (recording).mp4` (требование «недописанный ролик не выглядит законченным»; fMP4 при этом проигрывается до текущего момента). Пишем через `openFileDescriptor("rw")` → `ParcelFileDescriptor.AutoCloseOutputStream` → `FileChannel` в `FragmentedMp4Writer`; дескриптор закрывается один раз, через канал, чтобы MediaProvider узнал о конце записи. Через 3 с после закрытия ролик переименовывается в настоящее имя (`update(DISPLAY_NAME)`). Если приложение остановилось раньше (обрыв питания, убитый процесс, обновление), при следующем старте сервис переименовывает свои ролики «(recording)»; строки, у которых файла уже нет, удаляет.

Почему не так, как задумывалось сначала (проверено на SM‑X115, Android 16, 2026‑11‑11):
- `IS_PENDING = 1`: MediaProvider удаляет такие строки, когда процесс приложения убит или приложение обновлено (`Deleted … items on external_primary due to com.universalkm.motion`) — записанное до обрыва пропадало.
- Скрытое имя с точкой: после закрытия строка становится «не медиа» (`media_type=0`), переименование переносит файл, но оставляет строку, и сканер заводит новую строку без владельца.
- Переименование сразу после закрытия (пока MediaProvider сканирует файл): та же новая строка без владельца. Такой ролик приложение больше не видит и не может удалить по пределу. Через 3 с переименование сохраняет строку и владельца.

Уборка — при открытии и после закрытия каждого ролика: запрос своих строк `MediaStore` без «(recording)» (приложение видит только свои записи без разрешений — значит, чужие файлы удалить нельзя в принципе), сортировка по дате, удаление старых до предела. Свободное место — `StatFs` общей памяти; < 500 МБ → состояние `low_space`, новые ролики не начинаются.

### D8. Окно камеры, строка в панели и окно файлов
- Управление — в отдельном окне (просьба владельца 2026‑11‑11: не загромождать панель). `MotionCameraWindows` — одно окно на устройство по peer ID, повторное открытие выводит его вперёд; пока открыто хоть одно окно, `MotionCameras` опрашивает состояние раз в 5 с.
- В окне: «Записывать при движении» с выключателем и строкой состояния, установка/обновление, выбор камеры (свои радиокнопки: `Picker` не умеет отключать отдельный пункт, а «Обе» на устройстве без пары камер должно быть недоступно), чувствительность, задержка, качество (в режиме «Обе» недоступно — 720p), предел места, число роликов, «Записи…».
- В панели (`MenuBarView.swift`) — раздел «Motion Camera» с одной строкой на устройство: краткое состояние и «Камера движения…». Строка есть у устройств с `fileTransport` и у тех, где камера стояла раньше (`known`, в `UserDefaults`).
- `FileBrowsers.show` получает необязательный `folder: RemotePath`; если окно открыто — переходит в папку. `FileBrowserModel.reveal` открывает родителя (`Movies`), если папки ещё нет.
- `--motion-window <adb transport> [name]` — только окно камеры одного устройства, без захвата ввода и транспортов (как `--files-window`), чтобы проверять рядом с запущенным UniversalKM.
- Строки — на 10 языков через `scripts/localization.py`.

### D9. Проверочная команда `simulate`
`am start … --ei simulate N` считает следующие N секунд движением (не больше 30 минут). Нужна, чтобы проверять сценарии записи на устройстве без человека перед камерой. Доступна только через `adb` (та же защита `DUMP`), в интерфейсе её нет.

### D10. Две камеры сразу
`CameraPipeline` — всё, что относится к одной камере (сессия, кодер, детектор, правило ролика, буфер, файл); `MotionService` держит одну или две. «Обе» — только если `CameraManager.getConcurrentCameraIds()` содержит набор с задней и передней камерой: тогда два конвейера по 720p (Android гарантирует для одновременной работы потоки до 720p/1440p, берём с запасом). Иначе — задняя камера и строка в журнале. Состояние отдаёт `both` (умеет ли устройство) и `active` (какие камеры пишут сейчас); общее состояние — «пишет», если пишет хоть одна. В имени ролика при «Обе» — камера: `2026-11-10_14-32-05 rear.mp4`. SM‑X115: `Concurrent ID combinations: None` — «Обе» недоступно. Устройство с поддержкой для проверки пока не найдено.
*Альтернатива:* по очереди переключать камеры (теряется предзапись и полсекунды на каждое переключение — пропуски движения).

### D11. Живая картинка: кадры кодера через локальный сокет
Телефон не кодирует ничего второй раз: `LiveHub` отдаёт те же кадры H.264, что идут в ролики, через `LocalServerSocket` `ukm-motion-live`. Mac делает `adb forward tcp:0 localabstract:ukm-motion-live`, шлёт строку `back`/`front` и получает пакеты `C` (размер, SPS, PPS) и `F` (время, ключевой ли, поворот, Annex B). Сокет пускает только uid `shell` (2000) и `root` — как `DUMP` у команд. Клиент начинает с ключевого кадра (раз в секунду); кто не успевает (очередь больше 45 кадров), пропускает до следующего ключевого. На Mac кадры идут в `AVSampleBufferDisplayLayer` (`DisplayImmediately`), поворот — поворотом слоя.
Какие камеры открыты: запись (если включена) плюс те, что смотрит Mac (`--es live back|front|both|none`, не сохраняется). Две разные — только при паре из `getConcurrentCameraIds`, тогда обе по 720p; иначе запись важнее, и окно объясняет. Камера, которая уже пишет и остаётся, не переоткрывается — ролик не рвётся. Нет клиентов 20 с — просмотр заканчивается, при выключенной записи сервис останавливается. Камеры открываются по очереди: на S10e вторая, открытая во время настройки первой, ломала её сессию. Первая повторная попытка после отказа камеры — через 2 с: штатная «Камера» Samsung, оставленная открытой под блокировкой, забирает камеру на миг, когда закрывается `ControlActivity`.
*Альтернативы:* второй кодер поменьше (лишняя нагрузка и переконфигурация сессии во время ролика); `scrcpy`-подобный захват экрана (нужен экран и предпросмотр).

### D12. Красная точка на значке и фоновый опрос
`MotionCameras` читает состояние раз в 5 с: всех устройств, пока открыто окно камеры или «Вживую», и только устройств с камерой — всегда (одна команда `content query` на устройство). `anyRecording` → `RecordingDot`, вид поверх кнопки значка, чтобы точка жила при смене картинки (Mac / устройство). Долгая установка: через 15 с окно объясняет проверку Play Защитой (на S10e первая установка шла 1–2 минуты); через 3 минуты процесс `adb install` убивается, и если приложение всё же стоит — установка считается законченной.

## Risks / Trade-offs

- [Samsung/другие прошивки убивают фоновый сервис] → `deviceidle whitelist`, `RUN_ANY_IN_BACKGROUND`, проверка сутками в задаче 5.2; в README — где на телефоне отключить «Оптимизацию батареи», если прошивка всё равно убивает.
- [После перезагрузки Android 15+/16 не даёт запустить Activity из фона] → уведомление «Включить камеру» (одно нажатие). Это предусмотрено в спеке.
- [Нагрев и батарея при круглосуточной камере] → кодер 720p по умолчанию, анализ 5 к/с на маленьком кадре; в README — держать на зарядке; останов при 10 %.
- [Ролики по 60 с неудобно смотреть подряд] → имена по времени, сортировка по имени в окне файлов даёт порядок. Склейка — вне изменения.
- [Ложные срабатывания (тени, телевизор, автофокус)] → три уровня чувствительности, два кадра подряд, сброс фона при смене света. Зоны — вне изменения.
- [Потеря ключа подписи] → резервная копия (D2); иначе переустановка с удалением.
- [Индикатор камеры и уведомление нельзя скрыть] → так и задумано (приватность), в README сказано.

## Migration Plan

Новое приложение и новый блок панели; у кого камеры нет, ничего не меняется. Откат — убрать блок из панели; приложение на телефоне удаляется обычным способом или `adb uninstall com.universalkm.motion` (записи в `Movies` остаются).
