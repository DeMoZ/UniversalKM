# Proposal

## Why

Мышь и клавиатура Mac уже работают на Android по USB (AOA2) и по Wi‑Fi (ADB), а общего буфера обмена нет. Текст, скопированный на Mac, нельзя вставить на телефоне, и обратно. Приходится пересылать его себе в мессенджере. Когда телефон подключён через `adb`, на нём можно запустить код с правами `shell`, а этим правам Android даёт читать и записывать буфер обмена и узнавать о его изменениях (так работает scrcpy). Значит, общий буфер можно сделать без приложения на телефоне и без нового железа.

## What Changes

- **Общий текстовый буфер Mac ↔ Android в обе стороны** для телефонов из схемы, у которых есть связь `adb`: по Wi‑Fi или по кабелю при включённой отладке по USB.
  - Mac → Android: при изменении буфера Mac новый текст сразу попадает в буфер телефона.
  - Android → Mac: при изменении буфера телефона (копирование пальцем или с клавиатуры Mac) новый текст сразу попадает в буфер Mac.
- **Помощник на телефоне без установки.** Приложение кладёт на телефон маленький файл `.dex` (в `/data/local/tmp`) и запускает его через `adb shell app_process`. Помощник держит связь с Mac, пока телефон подключён. При отключении он завершается, на телефоне ничего не остаётся работать.
- **Только текст.** Картинки, файлы и форматирование не передаются. У длинного текста есть предел размера.
- **Пароли не уходят.** Содержимое, которое программы на Mac помечают как скрытое или временное (менеджеры паролей), на телефон не передаётся.
- **Переключатель в панели** у каждого Android‑устройства: «Общий буфер обмена», по умолчанию включён. Если `adb` для телефона нет (только AOA), панель показывает, что буфер недоступен и что для него нужна отладка по USB или Wi‑Fi.
- **Документация:** раздел «Общий буфер обмена» в README.md и README.ru.md.

Вне этого изменения: «напечатать буфер» нажатиями клавиш для AOA и Chameleon (iPhone/iPad), картинки и файлы, буфер между несколькими телефонами.

## Capabilities

### New Capabilities

- `android-clipboard-sync`: общий текстовый буфер обмена Mac ↔ Android через `adb`. Покрывает условия доступности, обе стороны передачи, защиту от эха, ограничения (только текст, предел размера, скрытое содержимое), переключатель и состояние в панели, поведение при потере связи.

### Modified Capabilities

(нет: в `openspec/specs/` ещё нет спецификаций. Изменение опирается на незаархивированный `add-android-usb-transport` (`android-wifi-link`, `android-usb-link`) и его требования не меняет.)

## Impact

- **Телефон:** новый исходник помощника на Java (`android/clipboard-helper/`). Он обращается к скрытому системному `IClipboard` через reflection, сигнатуры зависят от версии Android. Готовый `ukm-clipboard.jar` с `classes.dex` лежит в `Resources/`, так что сборке приложения Android SDK не нужен. Пересборка помощника — `scripts/build-android-helper.sh` (`javac` + `d8` из build-tools).
- **Приложение:** новый `ClipboardHelperLink.swift` (процесс `adb shell app_process`, строки протокола), `ClipboardSync.swift` (наблюдение за `NSPasteboard`, фильтр скрытого содержимого, защита от эха, маршрутизация по телефонам). Правки `AndroidHIDTransport` (какой `adb`‑транспорт у телефона), `AppStateManager`, `MenuBarView`, строк локализации, `scripts/build-app.sh` (копирование jar).
- **Core:** `ClipboardProtocol.swift` (кодирование и разбор строк протокола, предел размера) — с unit‑тестами.
- **Сохранённые данные:** флаг «Общий буфер обмена» для каждого peer ID Android в UserDefaults.
- **Разрешения macOS:** возможно, одно. Новые версии macOS могут спрашивать пользователя, когда программа читает буфер без его действия («вставить из других приложений»). Есть ли такой запрос на текущей системе и как он выглядит, проверяется в задаче 1.3 (design D6).
- **Ограничения:** нужен `adb`‑доступ (режим разработчика). Только Android 10+ (помощник проверяется на Samsung S10e, Android 12).
