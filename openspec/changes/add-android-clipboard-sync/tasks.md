# Tasks

Исходная точка: ввод Mac → Android по AOA и ADB работает (`add-android-usb-transport`). Буфер — через помощник `app_process` от пользователя `shell` по `adb`, только текст, в обе стороны (design D1–D5). Проверочное устройство — Samsung S10e, Android 12.

## 1. Спайк: помощник на телефоне и буфер macOS

- [ ] 1.1 Черновой помощник (`android/clipboard-helper`, design D1, D3) и `scripts/build-android-helper.sh` (D7): `hello` с `sdk`, `set` пишет в буфер, подписка шлёт `changed`. Запуск вручную: `adb push` + `adb shell CLASSPATH=… app_process / com.universalkm.clipboard.Main`, строки вводятся руками. Проверка на S10e: `set` с «Привет 👋\nстрока 2» → вставка на телефоне даёт тот же текст; копирование пальцем → строка `changed` за ≤ 1 с; закрытие stdin → процесса нет в `ps -A`. Найденные сигнатуры `IClipboard` и работает ли подписка (или нужен опрос) — записать в design D3.
- [ ] 1.2 На том же телефоне: появляется ли системное всплывающее окно при записи и есть ли диалог при чтении из `app_process`. Проверка: результат записан в design (Risks и Open Questions).
- [ ] 1.3 macOS: чтение `NSPasteboard` из подписанного `UniversalKM.app` в фоне. Значение `accessBehavior`, появляется ли системный запрос, что видно в «Конфиденциальность и безопасность». Проверка: результат записан в design D6; если запрос есть, D6 уточнён до начала группы 3.

## 2. Core: протокол

- [ ] 2.1 `UniversalKMCore/ClipboardProtocol.swift` (design D2): кодирование `set`/`ping`, разбор `hello`/`changed`/`ack`/`pong`/`error`, base64 UTF‑8, предел 1 МБ, версия протокола. Проверка: unit‑тесты — кириллица, эмодзи, `\n` и `"` в тексте дают одну строку без переводов строк внутри и восстанавливаются без искажений; 1 МБ + 1 байт → отказ; мусорная строка → `nil` без падения.
- [ ] 2.2 Решение «рассылать или нет» в Core (design D5): чистая функция от типов буфера, текста, `changeCount`, последней своей записи и последнего отправленного на каждый peer. Проверка: unit‑тесты — `ConcealedType`/`TransientType`/`AutoGeneratedType` → не слать; только картинка → не слать; своя запись → не слать; текст с телефона A не уходит на телефон B; тот же текст повторно → не слать.
- [ ] 2.3 Тест совпадения версии протокола в Java и Swift (design D7). Проверка: тест падает, если поменять `v` только в одном месте.

## 3. Помощник и связь в приложении

- [ ] 3.1 Помощник до рабочего вида (design D3): перебор сигнатур, запасной опрос 500 мс, гашение эха после `set`, предел 1 МБ, `ping`/`pong`, выход по закрытию stdin. Собрать `Resources/ukm-clipboard.jar`, `build-app.sh` копирует его в приложение. Проверка: `scripts/build-app.sh` без `ANDROID_HOME` проходит, jar есть в `Contents/Resources`; ручные проверки 1.1 проходят на собранном jar.
- [ ] 3.2 `ClipboardHelperLink.swift` (design D1, D4): push по хэшу с проверкой `ls`, запуск, чтение и запись строк, heartbeat 2 с / 5 с, `onLost`, остановка ≤ 0,3 с закрытием stdin, удаление старых `ukm-clipboard-*.jar`. Проверка: в журнале `scripts/run.sh` — `hello v1 sdk31` от S10e по Wi‑Fi; второй запуск не делает push; выключение Wi‑Fi на телефоне → «lost» за ≤ 5 с.
- [ ] 3.3 `AndroidDeviceStatus` получает текущий `adb`‑транспорт телефона: USB‑`adb`, если он есть и `device`, иначе Wi‑Fi, `unauthorized` не считается (design D4). Проверка: unit‑тест выбора или журнал — телефон на кабеле с отладкой показывает USB‑серийный; без отладки и без Wi‑Fi — `nil`.
- [ ] 3.4 `ClipboardSync.swift` (design D4–D6): опрос `changeCount` 300 мс, фильтр по 2.2, запуск и остановка помощников по схеме, переключателю и транспорту, перезапуск при смене транспорта, отправка текущего текста при новом подключении, текст телефона → буфер Mac, без текста в журнале. Подключить в `AppDelegate`/`AppStateManager`, остановка при выходе. Проверка: вручную на S10e по Wi‑Fi — все сценарии требований «С Mac на Android», «С Android на Mac» и «Без эха» (для двух телефонов — unit‑тест 2.2, если второго телефона нет); `grep` журнала по скопированному тексту ничего не находит.
- [ ] 3.5 Потеря связи и выход (спека «Потеря связи и выход»). Проверка: кабель с отладкой выдернуть при живом Wi‑Fi — буфер работает дальше по Wi‑Fi; телефон вне сети минуту и обратно — буфер работает без действий пользователя; выход из приложения — через ≤ 2 с `adb shell ps -A | grep app_process` пусто.
